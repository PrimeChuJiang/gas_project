## 概念课（UE TargetActor）

- `UGameplayAbilityTargetActor` = "执行目标选择的载体"（Actor 活在场景）：
  ① 选择需要世界（物理空间）② 可能持续多帧 ③ 要视觉反馈 ④ 与 GA 解耦（GA 只认数据）
- Godot 与 UE 的分水岭：Node2D/Node3D 是兄弟类，TargetActor 基类落 **Node**
  （坐标系无关），2D/3D 子类各管查询——坐标系相关全推迟到子类

## 用户反复踩的坑（教学重点，第四次终于钉死）

**跳变沿判定的"顺序比较"病根**——同一结构错误出现四次变体：
1. 引用比较（old != new 实例）→ 每帧误发
2. 提前 return 吞后比字段（location 相同 return，actors 变化被吞）
3. if-elif 互斥吞分支（都 true + location 同 → actors 永不比）
4. 手改时 elif→if 丢 null 门卫（首次 select_at 崩）
**根治**：思维模型从"分情况处理"换成"找不同"——每个字段独立关卡、任何不同即 false、
绝不提前 return 跳过字段；`is_same_as` 四步：null → has_location → location → actors。

其他：
- 基类 51 行笔误 return false→true（select_area 成功路径）
- **GDScript lambda 值捕获实锤**：`var f := func(): count += 1; f.call()` 后 count 仍为 0
  （本地脚本验证）——lambda 捕获局部变量是快照，改不动外部；回调改状态必须走
  **成员变量 + 命名函数**（self 引用）或容器（数组/字典按引用）。项目 GameplayCue
  计数先例就是正确姿势。**新账，值得进文档。**
- intersect_point 返回 Array[Dictionary]（collider/collider_id/rid/shape），
  无位置字段、无顺序保证；重叠时"取第一个"不可靠 → z 排序记入想法清单
- get_meta 键不存在会 push_error → has_meta 守卫（或带默认值参数）
- Viewport.world_2d 存在（Godot 4.7 文档确认）——Node 也能拿 2D 空间

## 续：需求 2 WaitTargetData Task 关账（同日晚，已提交 54d416d 后）

### 实现（用户写，我审）

`GASAbilityTaskWaitTargetData`（extends GASAbilityTask）：
- `create(ability, target_actor)` 注入实例（非 UE 的传 class 自建——测试可控、2D/3D 通用）
- `activate`：super + `actor.start_targeting()`
- `confirm_selection() -> bool`：confirm_target → null 拒绝（返回 false 任务继续等）/
  有 → 存 `_target_data` + `end_task(false)`（**拒绝空确认**——"点空地不能确认技能"）
- `cancel_selection()`：actor.cancel_target + end_task(true)
- `end_task(canceled)` 覆写：**仅 canceled 时**善后 actor.cancel_target，再 super
  （能力打断 → GA end_ability 遍历 end_task(true) → 善后自动执行）
- 结果交付：**task 持有，能力 `get_target_data()` 读**（不造带参信号绕开唯一漏斗；
  信号回调时 task 还活着，queue_free 是下帧的事）
- 审查抓的坑：confirm 忘 end_task(false)（致命，任务永不结束）/ 变量名 target_actor
  装 TargetData（名实不符）/ end_task 无条件清选择（应在取消路径才清）/ create 参数
  Node→GASAbilityTargetActor（类型即边界）
